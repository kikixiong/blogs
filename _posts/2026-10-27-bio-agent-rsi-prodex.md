一个生物 Agent 完成了蛋白质分析：查数据库、调用预测工具、比较候选，再写出一份报告。这已经有实际价值。再往前走一步，我们想问：**完成这次任务之后，它有没有变得更会做下一次研究？**

这是我在做 Prodex 时越来越在意的问题。一次任务里，Agent 可以写出很长的分析，调用很多工具，也可以不断纠错。但任务结束之后，如果它只留下一个结果文件，下一次遇到相似问题仍然从头摸索，那么研究过程里的大部分经验其实没有进入系统。

我对生物 Agent 的 RSI——recursive self-improvement，递归自我改进——最感兴趣的地方，就在这里：**怎样让一次研究留下的经验，改变下一次研究的做法，而且这种改变确实有用。**

## 先让 Agent 有一个能工作的环境

对一个具体的蛋白研究任务，能回答问题只是开始。系统还要拿到正确的数据，理解工具的输入要求，把上一步产物交给下一步，并知道一次执行究竟成功了没有。一个数据库版本的变化、一处残基编号的错位，或者一个没有被正确解析的输出，都可能让后面的分析失去依据。

所以，我认为生物 Agent 很大一部分早期价值，会体现在这些连接处。研究者需要一个可以接续工作的环境：知道手上有哪些数据、哪些步骤完成了、哪些候选被淘汰、为什么停在这里。模型能力当然重要，但如果这些状态是混乱的，推理越长，核对它的成本也可能越高。

一个好用的研究工作台，本身就值得做。在此基础上，我还想进一步问：系统能不能学会什么时候用哪个工具、什么时候值得追加计算、什么时候应该承认现有证据不足？**工具环境提供行动的可能性，经验更新决定行动是否越来越有依据。**

这也是 Prodex 值得选择一个较窄切口的原因。面向具体蛋白任务，我们可以逐步追踪输入、行动、观察、候选比较与停止决定，从而把“它似乎更聪明了”转成可评估的研究问题。

## 先分清：研究对象变好了，还是研究者变好了

讨论 RSI 时，我习惯先看反馈究竟改变了什么。下面四种情形对应不同的改进对象，并不构成人人必须依次通过的等级。

| 情形 | 改变了什么 | 怎样检查 |
| --- | --- | --- |
| 任务内纠错 | 当前代码、计划或工具参数 | 修复能否解决当前错误，有没有引入新错误 |
| 科学探索闭环 | 当前假设、候选或下一次实验 | 新证据是否改变选择，结论是否得到独立支持 |
| 跨任务经验改进 | 以后会复用的记忆、Skill、检索或选择策略 | 在未用于生成这些经验的任务上，是否比原版本更有效 |
| 改进机制的递归更新 | 用来提出、验证或实现下一次更新的能力 | 改进后的系统能否继续产生有效后继版本，并排除额外数据、预算等解释 |

例如，Agent 根据一个新读数淘汰当前候选，体现了反馈驱动的决策。若它进一步总结出带适用条件的候选筛选规则，经验证后在后续任务中采用，就涉及持久的 Agent 状态更新。若新版本还参与改进下一代的更新过程，“递归”的含义才更强。

因此，不宜用“有没有修改模型权重”作为唯一分界。固定基础模型也能演化工具与执行策略；反过来，人手启动一次微调，也未必构成 Agent 自主改进。真正要检查的是：**谁提出更新、更新了什么、反馈从哪里来、什么被保留，以及下一轮怎样使用它。**

## 生物反馈最难的一点：什么才算做对了

我觉得生物场景里最容易混淆的，是把“系统得到了一个更好的数字”理解成“研究取得了进展”。工具成功返回、计算评分提高、独立数据支持、真实实验成立，这几件事之间都有距离。

例如，我们让 Agent 筛选蛋白候选。如果它反复围绕同一个预测器搜索，最后得到更高的预测分数，至少说明它更会优化这个评分器。但这个结果是否对应目标性质的改善，还需要别的证据。若把所有高分轨迹都写成成功经验，系统可能越来越熟悉评分器的偏好，却没有更接近原来的科学问题。

这会让自改进出现一个危险的方向：系统持续积累经验，指标也持续上升，但这些经验主要教会它如何迎合自己的评价方式。因此，我希望保留下来的经验始终说明，它到底得到了哪一层支持。

反馈也未必来得及时。计算结果可以很快返回，独立验证可能晚得多；有些候选始终没有被验证。这意味着“尚未失败”不能自动变成“已经成功”，暂时没有结论的路线也不应被一律丢弃。经验库里需要容纳这些未完成的判断。

对 Prodex 来说，我想同时保留两类记录：当前问题取得了什么进展，以及系统采用了什么做法。前者帮助我们评价候选，后者才有可能转成下一次任务可用的经验。

## 我们在 Prodex 里先做什么

我们目前先把任务执行拆成 Plan、Action、Observation、Decision：形成计划，执行动作，取得观察，再决定继续、调整还是停止。已经实现的执行内核会保留逐轮轨迹、预算与停止原因，并支持轨迹层恢复和离线回放。这些能力让我有机会回头检查：某一步为什么发生，它依据的观察是什么。

这个范围也很明确：M1 依靠确定性的模拟工具验证控制流程，本身没有接通完整的真实蛋白模型研究闭环。项目中少量工具已有受限技术验证，其他工具仍在不同准备阶段。**工具曾经成功返回一个结果，不等于系统已经完成了生物验证。**

跨任务自改进则仍在设计阶段。我希望一次任务产生的反思，先成为一个候选更新，经过独立比较后再决定是否采用；采用之后还要观察它有没有导致退化，必要时恢复旧版本。当前的任务日志是可追溯记录，距离一个有效的经验库，还有提炼、验证与使用这几步。

所以，Prodex 当前的重点是：**为蛋白研究中的反馈决策与后续自改进，搭建可检查的执行和证据基础。** 我们还需要用后续实验回答，自改进是否带来收益、能否迁移到新任务，以及会不会损害原有能力。

## 最值得让它积累的，是有适用条件的决策经验

对于 Prodex，我倾向于让第一批持久更新从小范围的研究策略开始。它们容易检查，也方便在出现问题时定位原因。

设想一个抽象的蛋白候选筛选任务。Agent 发现，两种计算评分给出的排序不同。如果它只记住“上次选工具 A 得到了更高分”，经验很容易退化成对单个评分器的偏好。更值得保留的是：这次分歧发生在什么输入范围、评分各自衡量什么、哪个结论还没有外部证据，以及采用哪种后续检查能够减少不确定性。

一条可复用经验至少应包含四件事：**适用条件、建议动作、支持与反对证据、停用条件。** 比如某条工具选择规则只对特定任务类型成立，就不应自动升为所有蛋白任务的默认规则。只有一个成功案例时，也应保留“待验证”的状态。

这里还需要区分三类失败。工具超时或格式不兼容，首先是执行问题；程序正确运行但所测假设没有得到支持，是研究结果；代理分数上升却无法通过独立检查，则说明优化目标可能没有对准研究目标。它们需要不同的更新。把所有失败都压缩成“换一个方法再试”，会丢掉最有价值的因果线索。

由此可以形成两个紧密相连的研究问题：**哪些观察值得转成经验？什么检索规则能让经验在合适的任务上生效？** 保存更多历史只是起点，真正的贡献要体现在决策变化及其后果上。

## 怎样证明它真的在改进

我想先用三个逐步收紧的问题检验这条路线。

**第一，新观察有没有实际影响下一步？** 固定基础模型、工具和预算，比较固定工作流、普通工具循环和带显式状态与停止判断的外层循环。再在预先定义的测试场景中删除最新观察、交换候选与观察的对应关系，或将成功反馈改为可恢复失败。应对关键证据敏感、对无关扰动稳定；仅仅让动作发生变化还不够。如果这些干预都不影响决定，就需要重新检查系统是否真正使用了反馈。

**第二，持久经验有没有跨任务价值？** 在前一问题成立后，再比较原始历史可见但不额外整理经验的系统、检索成功案例的系统，以及检索带失败条件和适用范围的经验系统。各组的信息访问权限与预算要一致；额外记忆的检索和输入成本也要计入。否则，有效的是“多看了资料”还是“学到了更好的用法”，很难判断。

生成经验所用的任务、选择候选版本所用的开发任务，以及最终确认效果的保留任务，应分开。最终保留集不能反复用于挑选更新版本。在蛋白任务中，划分还应依据具体科学问题考虑同源性、蛋白家族、测定条件或数据来源；随机拆分记录并不自动代表新问题上的泛化。

**第三，新版本能否支持后续有效更新？** 只有一次经验迁移收益时，结论宜停在“该更新有用”。要进一步讨论递归改进，应比较多轮更新与控制条件：给它们相同数量的来源任务和总预算，排除“多看了几个任务”造成的收益；再看新版本是否持续产生有效后继版本，以及旧任务是否退化。若系统声称连改进机制本身都变强，还需专门比较新旧改进者提出和验证更新的能力。

可以把确认性比较写成一个很朴素的量：在相同未见任务和预算下，更新后版本相对旧版本的效用差。效用要在试验前定义，同时报告分布、失败与成本。一个更长的报告、更多工具调用或更高的自评分，都不能单独代替这个差值。

蛋白场景尤其需要把证据层次写清楚：工具正确运行，证明执行路径；预测器分数改善，证明在该代理目标上的优化；未参与选择的历史测定标签可以提供回顾性验证；前瞻性实验才能提供相应条件下的新实验依据。Prodex 当前是计算系统，前三者也必须分别表述，不能把计算产物改称生物观察。

## 把产品价值和研究贡献接起来

我对 Prodex 的期待有两个时间尺度。近期，它应该成为一个可靠的蛋白研究工作台，让研究者看见任务进展、比较候选、定位失败并接续工作。更长远地，它应该能把这些使用过程转成有边界、可验证的决策经验。前一个目标让系统有用，后一个目标让它有机会随着使用而改善。

实现上也有一个自然次序：先把单任务的执行与反馈关系做实，再检验跨任务经验，随后考虑工作流、工具策略或模型适应的版本更新。每次更新都应保留依据与退路，并由独立标准决定是否采用。评测标准若随候选一起漂移，就无法知道系统究竟改善了什么。

我希望未来能看到一个很具体的结果：给定相同的工具、任务与预算，Prodex 在新的蛋白研究案例上，能因为过去得到的经验，更准确地选择下一步，更早识别无效路线，也更清楚地说明哪些结论仍然没有证据。那时，一次研究留下的就不只是答案，还有下一次研究真正用得上的能力。
